# OpenMem 全自动改版 · UX 契约

- Status: 待与 P0 方案合版（本文件只定义 UX 约束，不含阶段排期）
- Scope: `console/` + `extension/` 的交互、信息架构、状态语义、文案与可访问性
- 方式: 只读审查现有代码；本阶段不修改任何产品代码、不启动服务、不读取真实数据目录
- 上游: `docs/goals/full-auto-memory/`（DESIGN / PLAN / ACCEPTANCE 由 P0 负责）
- 下游: phase05 产品实现（按本契约验收）

---

## 0. 结论摘要

1. 默认首页从「审批队列」改为「记忆」，默认语义 = **当前有效内容**，不是待办。
2. 一级入口收敛为 **记忆 / 活动 / 设置**；自动模式下**普通记忆零审批**：没有「待确认」主链路、没有红色催办徽标。legacy 审查入口收进「设置 › 高级与维护」，活动只记录事件，不做审批台换名。
3. 撤销从「健康页 + 每次确认弹窗」改为 **对象内联 + 活动流水 + 记忆筛选 + 历史全量** 四通道；可逆操作不弹确认。停用随时可用，且**从下一次模型请求起不再注入（包括已经开始的会话）**；版本回退默认建议 90 天、可配置，以后端正式契约为准。
4. 状态用 **三轴正交模型**：写入状态 / 运行质量 / 数据新鲜度。禁止合成成一个颜色或一句「SHADOW ON」。
5. 每处计数必须标注口径：**全部项目 / 当前项目 / 本次会话**；不可用显示「未知」，不得显示 0。
6. 「停止使用」「撤销/版本回退」「删除副本」是三种不同动作、三套文案、三种确认策略，禁止互相借用词；删除副本本轮只界定边界，不承诺全机擦除（含备份），未实现不显示入口。
7. 现有高级能力（健康、审计、图谱、技能审查、备份、历史、保留清理、legacy 审查）全部保留在「设置 › 高级与维护」，旧深链前端重定向。
8. 视觉不新增色板：沿用暖灰 + 墨绿 `--accent` 与既有语义 token；只新增字号阶梯、状态 chip 与层级规则。

## 3. 共享状态模型（三页必须一致）

### 3.1 三轴正交，禁止合成

| 轴 | 取值 | 来源 | 呈现 |
|---|---|---|---|
| 写入状态 `WriteState` | `pause` / `shadow` / `auto` | `config.shadow`、`config.autoMemory`、`health`、写入阻断（队列读失败） | 中性 chip；仅 `pause` 用 warning |
| 运行质量 `RunMode` | `normal` / `degraded` | decision/rewrite fallback、review 失败、限流、输出不合格 | `degraded` 用 warning 描边 + 原因 tooltip |
| 数据新鲜度 `Freshness` | `fresh` / `stale` / `unknown` | 最近成功读取时间；`/api/metrics` 是否可用 | `stale` 灰 + 时间；`unknown` 用「未知」而非 0 |

派生优先级：`pause` > `shadow` > `auto`（互斥）；`degraded`、`freshness` 与写入状态并存，三者同排显示，顺序固定：写入 → 质量 → 新鲜。

判定细则：

- `pause` 必须带原因：`user`（用户在设置里暂停）/ `write-blocked`（`load.writesBlocked`，队列读取失败）/ `capacity`（容量或磁盘预算触顶）/ `migration`（迁移进行中）。文案见 §8。
- `shadow=true` 时「自动写入」不成立，活动里的事件是「本来会写入」，不得出现「已写入」。
- `degraded` 不等于失败：队列仍可批准，文案固定为「降级运行 · 模板合并」，不遮断操作。
- `stale` 阈值 = `max(3 × 轮询间隔, 60s)`；`/api/metrics` 失败 = `unknown`，不是 `stale`（未读到 ≠ 旧）。

禁止：

- 把 `shadow` 写成「关闭 / 停用」；
- 把 `degraded` 写成「失败 / 异常」；
- 把 `unknown` 渲染为 0、`—`（`—` 只用于「该对象无此字段」）；
- 用单一绿色/黄色圆点概括三轴。

### 3.2 计数口径

每个数字必须同时给出「值 + 口径」：

| 口径标签 | 数据源 | 使用位置 |
|---|---|---|
| 全部项目 | `/api/metrics` 快照（`items/queue/shadow/auto/promoted`） | 侧栏徽标、活动聚合、顶栏 |
| 当前项目 · {name} | 当前 `projectKey` 过滤后的列表 | 记忆页 KPI、活动筛选结果 |
| 本次会话 | `scope=session` / `sessionNotes` | 记忆页「本次会话」段 |

硬规则：

1. 侧栏与顶栏数字固定「全部项目」，并在 `title` 与可访问名中写明；页面内 KPI 默认「当前项目」，筛选变化时标签必须同步变化，不得静默复用同一个词。
2. `metrics` 不可用：保留数字位，显示「未知」+ `aria-label="计数未知，指标接口不可用"`；不得塌陷布局、不得删除徽标。
3. 「生效中」不与任何审查计数合并；auto 模式下普通记忆不产生待确认数，legacy 审查计数只在「设置 › 高级与维护 › 审查（legacy）」内以中性数字显示。
4. 撤销/失败类计数必须带明确时间窗（与后端契约一致，如「近 24 小时」），不得暗示累计；窗口不是 24 小时时不得沿用 24 小时文案。

### 3.3 撤销语义：三种动作，三套文案

| 动作 | 语义 | 数据影响 | 确认 | 可逆 | 主要入口 |
|---|---|---|---|---|---|
| **停止使用** | 从下一次模型请求起不再注入（**含已经开始的会话**） | 保留条目、版本、历史；仅置为非生效 | 否 | 是 →「恢复使用」 | 记忆行内、记忆详情、批量 |
| **撤销 / 版本回退**（批准、合并、提升、停用等） | 回滚到该操作前的内容版本 | 版本校验通过后反向写；不丢后续编辑 | 否（内嵌预览代替） | 是（可重做：重新应用相同变更） | 记忆详情、活动流水、历史 |
| **删除副本**（能力未定，本轮不做承诺） | 仅删除本机 OpenMem 存储中实际存在的副本 | 范围与实现待与 P0 契约合版；未实现不显示入口 | 若实现则确认 | 否 | 记忆 › 更多（仅当能力存在） |

**生效时点（硬约束）**

- 停用或撤销成功后，**下一次模型请求**的上下文即不再包含该条，包括已经建立的会话；不要求等新会话、不要求重启。
- 不承诺撤回已经发出的模型请求、已经执行的工具动作或上游服务侧的数据；UI 不得暗示「从未发生过」。
- 停用后可随时「恢复使用」，恢复同样从下一次请求起生效；恢复的前提是条目仍存在且版本未被清除。

规则：

- 可逆动作（含批量）**不弹确认**：改为「清单预览 + 一次执行 + 整批一个恢复/撤销入口」。不可逆动作与大批量（≥10 条）**必须确认**，对话框必须包含：影响条数、覆盖范围、是否可恢复、实际删除范围。
- 批量可逆：≥2 条即进预览态（复用 `Queue.tsx:1474-1556` 的结构：已选/跳过及原因/超限/执行/取消）。
- 窗口：**停用随时可用、无窗口限制**；**版本回退默认建议 90 天、可配置**，实际可用范围以后端正式契约为准，UI 读取返回值，不写死天数。旧 merge journal 的 24 小时撤销只在 legacy 入口出现，并如实标注「旧合并记录 · 24 小时撤销窗口（legacy）」，**不得复用到新能力上**。超出可用范围时按钮不可点，文案为「不可回退 · 查看历史」，替代路径是历史版本或备份，不是「再撤销一次」。
- 撤销前必须做版本校验：仅当目标版本可安全逆转时才提交。若目标已被后续编辑改变，**不得**提供「仅恢复文本」这类会静默丢掉后续编辑的选项；应转为「停止使用」并说明原因（保留现有编辑，只是不再注入），或者提示用户先处理冲突版本。

文案红线（评审必查）：

- 不得用「删除」表达「停止使用」；不得用「撤销」表达「删除副本」。
- 「停止使用」成功后不得出现「已删除 / 已清理 / 已同步」。
- 「停止使用」不得写「不会再进入新会话」：正确表述是「从下一次请求起不再注入（包括当前会话）」。
- 删除副本若实现，只能说明本机实际范围（如 `items.jsonl`、shadow、journal），**不承诺全机擦除（含备份）**；文案必须写明「存储在本机，但配置的抽取模型可能接收脱敏内容，本地撤销不等于删除上游请求数据」。

## 4. 信息架构

### 4.1 三个一级入口

```
记忆 (#memory) ── 默认落地，当前有效内容
活动 (#activity) ── 事件流（默认全部事件）· 复盘
设置 (#settings) ── 写入策略 / 模型 / 容量 / 高级与维护（含 legacy 审查）
```

- 侧栏：品牌 → 三个 nav → 底部状态区（三轴状态 / 数据目录 / 版本 / 构建时间）。
- **没有红色催办徽标**：auto 模式下普通记忆不产生待办数；活动顶部只有中性聚合文字（数字 + 标签），不用红点、不用「去确认」。legacy 审查计数只在「设置 › 高级与维护 › 审查（legacy）」以中性数字出现。
- 顶栏：页面名 + 三轴状态 chip + 刷新；不做全局搜索（保持安静）。

| L1 计数 | 生效中 n · 当前项目 {name}；右侧「全部项目 n」小字 |
| L2 分段 | 生效中 / 本次会话 / 已停止使用 / 已过期 / 全部（auto 模式下**没有「待确认」分段**；legacy 审查在设置›高级与维护） |
| L3 筛选 | 范围（全局/项目/会话）、类型、来源（自动/复盘/手动）、时间 |
| L4 列表 | 标题（1 行）+ 摘要（1 行）+ chips（scope, kind, 来源, 生效时间）+ 状态 + 行内动作 |
| L5 详情 | 正文、来源链、版本历史、关联、动作区（危险区仅当删除能力存在） |

**行内动作**：`停止使用`（次要按钮，hover/focus 可见，触屏常显）；已停止的行显示 `恢复使用`。

**详情区**

1. 正文（可复制，长文折叠）
2. 来源：会话 ID → 消息 → 项目；`session-review` 条目显示逐字证据（沿用 `Queue.tsx:2093-2115` 的 evidence 样式）
3. 版本历史：时间线（v1…vn，动作、操作者、时间、差异摘要）；无版本接口时显示「当前实例未提供版本历史」——不伪造
4. 关联：相似 / 覆盖 / 冲突（复用 coverage 语义与 `coverageLabel`）
5. 动作：`停止使用` / `编辑`（若保留）/`撤销最近一次变更`（提交前做版本校验）
6. 更多：**仅当产品具备删除副本能力时**显示「删除副本」，并标注实际范围与「上游请求数据不在删除范围」；未实现则不显示该入口（禁止假按钮）

**空态**：`还没有生效记忆。自动写入开启后，符合条件的候选会直接出现在这里。`（legacy 审查有积压时，底部一行中性小字链接到 设置›高级与维护›审查，不用红色徽标、不做主按钮）

**会话段**：置于列表上方独立 section，带常驻说明「仅本次会话可见，不会进入长期记忆」+「会话结束后自动失效」。

### 5.2 活动

- 默认段 = **全部事件**，不是待确认。顶部一行聚合：`今日 自动写入 12 · 跳过 3 · 失败 1 · 撤销 0`，每项可点击变成筛选。
- 事件类型：`自动写入` `自动跳过` `失败` `撤销` `恢复` `停止使用` `复盘` `维护` `降级` `导入/迁移`
- 行结构：相对时间（`title` 给绝对时间）· 类型 badge · 对象链接（→ 记忆条目）· 原因/依据（1 行，可展开）· 结果（成功 / 失败 / 未知）· 动作（`撤销` | `查看`）
- 分组：按天；同日低频事件折叠为「其余 n 条」。
- 失败与跳过必须给出理由来源（模型超时 / 限流 / 校验不过 / 重复 / 容量 / 敏感信息），不得只显示「跳过」。
- legacy 审查不是活动的一部分：入口固定在 设置 › 高级与维护 › 审查（legacy），活动内**不提供「去确认」主按钮、不出红色角标**；auto 模式下普通记忆也不会进入那里。

### 5.3 设置

分组（每组一张 panel，不再 2 列平铺 10+ 张）：

1. **写入与自动化**：影子/自动开关、暂停所有写入（kill switch）、版本回退窗口（只读展示后端返回值，默认建议 90 天）、自动跳过策略
2. **模型与阈值**：System One / System Two / Session Review / thresholds
3. **容量**：caps + 磁盘预算
4. **高级与维护**：审查（legacy）、健康、审计、记忆图谱、技能审查、历史、备份（每行 = 名称 + 一行状态摘要 + 「打开」）
5. **环境**：数据目录、Console origin、决策 key 来源、版本/构建
6. **危险区**（独立 fieldset，danger 描边，置于最底，**仅当对应能力已实现时才显示**）：删除副本、迁移回滚、重置；不承诺全机擦除（含备份）

约束：`Settings.tsx` 的 revision / 草稿 / 冲突保护（`settings-diff.ts`、`draft-state.ts`）必须原样保留；分组只改外层组织，不改保存协议。

## 7. 撤销与状态反馈契约

### 7.1 四条可发现通道（全部必需）

| 通道 | 位置 | 内容 | 时限 |
|---|---|---|---|
| A 对象内联 | 记忆行 + 详情 | 状态 chip「已停止使用」+ `恢复使用` / `撤销` | 永久（直到状态再变） |
| B 活动流水 | 活动事件行 | `撤销` 按钮 + 影响摘要 | 按后端返回的可回退版本；legacy 合并记录单独标注 24h，过期变「不可回退 · 查看历史」 |
| C 记忆筛选 | 记忆分段 | `已停止使用(n)`、`可回退版本(n)` | 永久 |
| D 历史全量 | 设置›高级›历史 | 全部 journal / changelog / 维护撤销 | 永久（受保留策略） |

只有 A+B+C 同时存在才算「可发现」；仅 toast、仅 B、仅 D 均不达标（现 `PanelApp.tsx:80-81` 属于反例）。

### 7.2 反馈时序（每个动作统一）

| 阶段 | 表现 |
|---|---|
| 点击瞬间 | 按钮 loading，目标行 `aria-busy="true"`，其他动作禁用（不整页遮罩） |
| 成功 | 行内状态就地切换，焦点留在原位置（按钮文字改为「恢复使用」），`aria-live="polite"` 播报「已停止使用「标题」，下一次请求起不再注入，可在本行恢复」 |
| 失败 | 行内 error 文本（不弹窗），`role="alert"` 播报，数据保持原状，行不位移 |
| 结果未知（超时/网络断开） | 复用 `Queue.tsx:1388-1395` 的锁：明确「结果未知，已停止重复提交」，提供「已核对，解除锁定」 |
| 批量 | 预览清单（含跳过原因）→ 执行 → 结果卡（成功/失败/未知/跳过/超限）→ 整批撤销入口 |

### 7.3 聚合提醒（默认安静）

同一屏最多 **1 条** 顶部 banner，按优先级取一条：写入阻断 > 失败>0 > 降级持续>5min > 版本回退窗口即将到期（只提示一次）。其余问题就地显示在条目上。禁止条状 banner 堆叠（现 `Queue.tsx` 可同时出现 6 条：target / pending / orphan / message / error / load / baseline），也禁止把 legacy 审查积压做成催办条。

**状态**

| 降级 | `降级运行 · 模板合并` |
| 新鲜 | `刚刚更新` / `3 分钟前更新` |
| 过期 | `数据已过期 · 上次 12:40` |
| 计数未知 | `计数未知` |

**动作与结果**

| 场景 | 文案 |
|---|---|
| 停用 | `停止使用` → `已停止使用「{标题}」。从下一次请求起不再注入，包括当前会话。` `[恢复使用]` `[查看活动]` |
| 恢复 | `恢复使用` → `已恢复「{标题}」，从下一次请求起重新包含它。` |
| 撤销合并 | `撤销合并` → 预览：`撤销后：「{目标}」回到合并前的文本，本次新建的条目会被归档。` `[撤销] [保留结果]` |
| 撤销批准 | `撤销批准` → `撤销后：条目回到操作前的状态，不会删除内容。` |
| 版本冲突 | `这条记忆在本次操作后又被修改过。为避免覆盖新内容，不能直接回退。` `[停止使用并保留现有内容] [查看版本对比]` |
| 不可回退 | `不可回退 · 查看历史`（不可点，`aria-disabled`）；legacy 记录追加 `旧合并记录 · 24 小时窗口（legacy）` |
| 删除副本（仅能力存在时） | 标题 `删除这条记忆的本机副本？` 正文 `只删除 OpenMem 在本机存储中实际存在的副本（{n} 处）；备份不在本操作范围内，也不删除上游模型已接收的请求数据。此操作不可撤销。` 按钮 `删除副本` |
| 批量可逆 | 预览标题 `批量停止使用 · {n} 条` 正文 `执行后可在活动中整批恢复；可回退范围以后端契约为准。` 按钮 `停止使用 {n} 条` |
| 结果未知 | `操作结果未知：{动作}。已停止重复提交，请先刷新核对。` `[已核对，解除锁定]` |
| 空记忆 | `还没有生效记忆。自动写入开启后，符合条件的候选会直接出现在这里。` |
| 空活动 | `今天没有事件。自动写入、跳过和失败都会记录在这里。` |
| 跳过原因 | `未写入：与现有记忆重复（相似度 0.91）` / `未写入：命中敏感信息规则` / `未写入：模型超时，已降级` |

**禁用词**

`删除`（指停用）、`已清理`（指可逆）、`不会再进入新会话`（停用效果）、`全机擦除 / 彻底清除`（本轮不承诺）、`置信度 87%`、`准确率`、`同步成功`（无服务端确认时）、`SHADOW ON`（对外英文缩写）。

**百分比规则**

- 只允许两处百分比：`相似度`（去重/合并候选，需 tooltip 定义）与 `采纳率`（必须给分子/分母与时间窗）。
- 禁止把 confidence 呈现为「正确率 / 可信度 / 把握」。
- 健康分必须标注「综合得分，不是正确率」，并在无数据时显示「未知」而非 100%（修 `Health.tsx:328` 的 `?? 1`）。

## 13. 与 P0 契约合版事项（不是本契约的强制依赖）

本契约**不新增后端 API 要求**。下表是合版时必须对齐的语义；未对齐时按「UX 兜底」降级，不阻塞前端落地。

| ID | 合版事项 | 现状 | UX 兜底（不追加接口要求） |
|---|---|---|---|
| C1 | 「下一次请求即不再注入」的准确实现（含进行中会话） | 由 P0 契约确认 | 文案固定按「下一次请求」写，不写「新会话」；不承诺撤回已发出的请求或已执行动作 |
| C2 | 版本回退范围（默认建议 90 天、可配置） | 由后端返回 | UI 读返回值；无值时不写死天数，显示「可回退范围见历史」 |
