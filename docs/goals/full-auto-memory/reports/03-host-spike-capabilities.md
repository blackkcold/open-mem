## 0. Review correction (documentation only; history kept)

- **Original error, now corrected:** this report previously listed `ctx.session.skill` and `ctx.session.instructions.entry` as plugin-context calls. In 2.1.4, `Context.session` is `SessionDomain = Pick<SessionApi, ...>` and the Pick has **no `skill` and no `instructions`** (`@opencode/plugin/dist/promise/session.d.ts:144-146`; `plugin.d.ts:25-54`). Those two names are full-client `client.session.*` methods, not plugin `ctx.session` methods. B3/C6 are rewritten; the old claims are void and retained only in this note.
- **Version basis:** static types are 2.1.4; the runtime CLI is 2.1.1. No 2.1.1 schema is present here, so static correctness is **not** runtime usability. Do not install/upgrade CLI/SDK to hide this. Future isolated-host probe should read OpenAPI plus the actual plugin `ctx` keys; until then rows stay **not-run/U**.
- `ctx.skill` is `SkillDomain` (`list`, `transform`, `reload`), not session skill activation (`@opencode/plugin/dist/promise/skill.d.ts:1-16`).

## 3. Minimal probe sequence (one run, few round trips)

1. Start isolated host + probe plugin + fake provider (runner-owned; not this report).
2. Create `rootA` in repoA, `rootB` in repoB, `childA` with `parentID=rootA`. Compare `create` return, `session.get`, `session.created` events. Assert A1–A4; record **U** if event/get disagree.
3. Send in rootA, in order: normal user text, user text with `metadata:{synthetic:true,warming:true}`, `ctx.session.synthetic`, full-client `client.session.skill` or HTTP `POST /api/session/{id}/skill`, a `<context>…</context>` text as user. Read `context`, paginated `message.list`, and `export(sanitize:false)`. Assert B1–B6, C1–C4.
4. Append a probe-only `SystemPart` in `context` hook; put `spike.entry` through full-client `client.session.instructions.entry` or HTTP PUT (not `ctx.session.instructions`); call one prompt. Capture `http.request` clone and fake-provider body. Assert C5–C7 and D1–D2. Then remove entry via full client/HTTP.
5. Call `ctx.generate.text` with a fixed prompt; assert no new session/message and no tools in fake-provider body. Separately call `ctx.session.generate` to prove the `generate` hook/positive control. Assert C8.
6. Repeat step 3 read-only with no writes; recompute hash; assert C4 idempotence. Do not infer raw-byte fidelity beyond chosen fields.
7. Record every field exactly as returned, including missing/undefined; do not normalize away `parentID`, `projectID`, `type`, `metadata`, or `native`.

## 4. Hard gates / do-not-claim list

- **Pass only if:** root/child `projectID`/`location`/`parentID` are present and consistent; native `user`, `synthetic`, `skill`, `system` types match the SDK; unmarked user text is not claimed synthetic; `entry.put` is observed in the next outbound request; `generate.text` creates no session/tools; fake provider accepts SSE and the assistant text is fixed.
- **Gap/unknown if:** no `template/context` native type, metadata is client-controlled, no per-part provenance, `context` differs from `message.list`/`export`, or `http.request` does not cover no-session generate.
- **Do not claim:** “host marks synthetic” from a hand-written `metadata.synthetic`; “user-authored” from `type:"user"` alone; “not an instruction” because it is `entry.put`; “no tools” from docs without the fake-provider body; “raw transcript” from `context` without C2/C3 comparison; any permission/security isolation from a type field.
- **Not-run:** all A–D runtime observations, all hashes, all SSE captures, all host events. Only SDK/DOC static facts are established here.
